> what does this project do?                                                    

● Kivora is a daily sales data pipeline for a fictional online fashion shop.
  It's built as the starting repo for a course assignment: you take over the
  pipeline and evolve it with a coding agent over six phases (assignment.md).

  What it does:

  1. Input. Each day the shop drops a folder in data/inbox/<day>/ with
     orders.csv, customers.csv and payments.csv. These are only new or changed
     records, with timestamps in UTC and amounts in each order's own currency
     (EUR, GBP or USD).
  2. Load. kivora/ingest.py loads the files as raw text into a SQLite database
     at output/warehouse.db, along with the exchange rates in
     data/reference/fx_rates.csv.
  3. Transform. The SQL in sql/ builds staging tables, then two business tables:
     - daily_sales: number of sales and gross amount in EUR per day and country,
       for the sales dashboard. Its rules are written down in
       docs/data-contracts/daily_sales.md.
     - top_customers: the 10 customers who bought the most.
  4. Output. It exports both tables as CSV files to output/.

  You run it with uv run python tasks.py run, which calls python -m kivora 
  --inbox data/inbox --reference data/reference --out output. That interface
  must not change. Tests run with uv run python tasks.py test.

  Its current state (from my analysis in this session):
  - It runs, but daily_sales breaks its own rules. It uses the UTC date instead
    of Madrid time, leaves the country blank instead of writing UNKNOWN, and
    never converts GBP or USD to EUR. It also ignores which version of an order
    is the latest. And an order with two captured payments would be counted
    twice.
  - On the real data, the totals are wrong. It reports 7840.72 where the
    contract gives 7905.15.
  - The 4 tests all pass anyway. One of them repeats the same mistakes as the
    code, so it can't catch them.
  - The old CLAUDE.md is mostly wrong. It points to a run.py and a queries/
    folder that don't exist, gives a test command that finds no tests, and
